# swift-iterator

Use this package to write or drive an iterator whose elements, iterator or source may be `~Copyable` or `~Escapable`, with typed failures. Conform a single-pass, element-at-a-time source to `Iterator.Protocol` (also spelled `Iterating`). Conform a type that can be walked repeatedly by borrowing to `Iterable`, whose iterator conforms to `Iterator.Chunk.Protocol` and lends contiguous spans; `Iterator.Chunk<Element>` lends from a `Swift.Span`, and `Iterator.Materializing<Source>` turns an element iterator into a chunk iterator. To look ahead and push elements back, wrap a source in `Iterator.Buffered<Base, SourceFailure>`, or call `bufferedIterator()` on a `Swift.Sequence` or an `Iterable`. For lazy adapters and sequence-level operations, use swift-sequence; for index-based access, use swift-collection.

## Laws

- `Iterable` is multipass: `makeIterator()` borrows its source, so `forEach`, `contains(where:)`, `first(where:)` and `reduce(into:_:)` can run on the same value any number of times and see the same elements in the same order.
- Chunk demand: `next(maximumCount:)` lends at most `maximumCount` elements. An empty span after a positive request means the iterator is exhausted. A request for zero elements returns an empty span, does not advance the iterator and does not read the source; `Iterator.Materializing<Source>` attempts a fallible read, and so can fail, only for a positive request.
- `Iterator.Materializing<Source>` lends at most one element per request, whatever the demand.
- The derived element `next()` on a chunk iterator requests one element at a time.
- The default `skip(by:)` returns how many elements it actually skipped. That is less than requested only when the iterator ran out; skipping zero reads nothing.
- `forEach`, `contains(where:)`, `first(where:)` and `reduce(into:_:)` stop at the first error thrown by the closure, and `contains(where:)` and `first(where:)` also stop at the first match. Elements already handed to the closure stay handed over. When the iterator itself can fail, a closure error arrives as `Either.left` and an iterator failure as `Either.right`.
- `Iterator.Once<Element>` yields its element once and then `nil` on every later call. `Empty` yields `nil` on every call. `Iterator.repeating(_:)` never ends.
- `Iterator.Buffered<Base, SourceFailure>` returns pushed-back elements before reading the base, the last one passed to `unread(_:)` first. Each pushed-back element is returned exactly once, by move. Pushed-back elements are owned by the buffer, so it can hold lookahead from a source whose elements borrow scoped storage.
- `bufferedIterator()` on a `Swift.Sequence` consumes the sequence and calls its `makeIterator()` exactly once.
- With the `Repetition` trait, `forEach(in:_:)` on a `Cardinal.Range` or on a `Repetition` with a `Predicate` reads at most the range's maximum number of elements and never one more. The predicate borrows each element; an element it rejects is pushed back into the buffer and stays the next element of the input. Every accepted element is moved into the closure exactly once. If fewer elements than the minimum were available, the elements already delivered stay delivered and the call fails, reporting how many there were. Empty bounds fail before any element is read.
- With the `Search` trait, `forEach(in:_:)` on a search selection yields every element before the first occurrence of the delimiter. Selecting `.start` leaves the whole delimiter in the input; selecting `.end` yields the delimiter as well and consumes it. If the input ends without the delimiter, or the input fails, the partly matched candidate elements are pushed back, so the input still holds them. `Search(sequence:)` reads its sequence once, so a single-pass sequence can serve as the delimiter of a selection that is used repeatedly.
